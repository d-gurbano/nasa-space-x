# Rewind website rework plan

Audit of https://rewind.up.railway.app/ (desktop 1024×768, tablet 768×1024, phone 375×812), 2026-11-15.
Written as instructions for Claude Code. Work through the phases in order; each phase ends in a commit.

Source of the site: `web/` (Vite + TypeScript + three.js). Some copy is generated by the engine
(`engine/rewind_engine/*.py` writes text into `object.json` / `benchmark.json`), so a wording fix may
need to land in **both** `web/src/**` and the engine, then the data has to be regenerated
(`web/scripts/sync-data.sh`). Never change a number by hand in the UI: fix it at the source.

---

## Phase 0 — Ground rules for this rework

1. **Do not change any measured value.** Copy changes only re-describe numbers that already exist in
   the JSON. If a sentence and a number disagree, find which is right in the data and fix the other.
2. Keep a single glossary and use it everywhere (UI, engine text, `docs/`, `DATA-CONTRACT.md`):

   | Term | Definition to use on the site |
   |---|---|
   | **Precovery** | A detection of an object in images taken before its discovery, found after the fact. |
   | **Discovery date** | Date of the discovery observation, per MPC / JPL SBDB. |
   | **First known observation** | Earliest observation in the MPC record (may be earlier than discovery, e.g. other surveys' precoveries). |
   | **Lead time** | Days between the earliest SPHEREx detection and the first known observation. Always say which reference date is used. |
   | **Shift-and-stack** | Co-adding image cutouts shifted along the predicted motion so a moving source adds coherently. |
   | **S/N (null-calibrated)** | Stack signal divided by the scatter of the same stack along off-target "null" paths. Say "null-calibrated S/N" once per page, then "S/N". |
   | **Null paths** | Synthetic trajectories offset from the predicted one; used to measure the false-detection rate. |
   | **Injection–recovery** | Synthetic sources planted at the predicted brightness to measure completeness at that spot. |
   | **3σ positional uncertainty** | Semi-major axis of the 3σ uncertainty ellipse from N covariance clones, at a stated epoch. |
   | **Verdict classes** | FOUND / HINT / TOO FAINT / NO DATA, defined once (see Phase 2.4). |

3. Write for an educated reader (science journalist, amateur astronomer, Space Apps judge). Plain
   but precise. Use the real term, then a short gloss the first time: "shift-and-stack (adding the
   images along the object's path)". Not the other way round.

## Phase 2 — Rewrite the wording (less "AI slop", more science)

### What reads as AI slop now, and why

- **Slogan stacking and drama**: "Every discovery has a past.", "Watch for the flash: SPHEREx saw it
  before anyone knew.", "13 days before anyone else", "Nobody knew it yet". Cute once; on every
  screen it reads as marketing, and "before anyone else" is false when other surveys have precoveries.
- **Anthropomorphising the pipeline**: "Rewind said Too faint and did not guess", "asked Rewind",
  "Rewind found it blind". Say what the algorithm did.
- **Vague hedges and filler**: "How sure are we?", "Bright enough to see here", "Many possible
  paths searched", "Does it work?", "Play with real space photos.", "Go further".
- **Childlike simplifications that lose the meaning**: "photos" for calibrated L2 images, "colours"
  for spectral channels, "dots" for asteroids, "made-up paths" for null trajectories, "a little too
  early or too late" for time-shift test.
- **Repetition**: the same 265 / 8 / 18,187 stat row appears on Home, About, Scientists with
  different labels ("found in older photos", "found, 7 of them before…", "Found").
- **Hyphen-for-dash typography**: "Real data - NASA SPHEREx". Use an en dash or a middot.

### 2.1 Copy deck (replace these strings)

Use these as the target voice; adjust numbers from data, never from this file.

**`index.html` meta + `src/ui/opening.ts` (hero)**
- Kicker: `NASA Space Apps 2026 · SPHEREx challenge`
- Title: keep "Every discovery has a past." (it's a good brand line) — but **only here**.
- Lede: "Rewind searches NASA SPHEREx survey images for newly discovered asteroids and comets in the
  weeks *before* their discovery. Each precovery adds an earlier position, which extends the
  observed arc and can tighten the orbit."
- CTA: `Explore the precoveries` (secondary: `How it works`)
- Stats: `8 precoveries` · `265 objects searched` · `18,187 SPHEREx images analysed`

**`src/ui/opening.ts` / `src/demo.ts` captions (guided intro)**
- "These dots are real asteroids and comets…" → "Each point is a known asteroid or comet, placed by its catalogued orbit (JPL SBDB)."
- "Watch for the flash: SPHEREx saw it before anyone knew." → "Highlighted: a SPHEREx image that recorded the object before its discovery."

**Object panel (`src/ui/panel.ts`, `src/ui/panel-text.ts`)**
- "13 / days before anyone else" → "13 days / earlier than the first known observation (15 Sep 2026)"
- Tabs: Photos → **Images**, Found? → **Evidence**, Future → **Orbit**, Made of → **Spectrum**, Story → **Discovery**
- "What SPHEREx saw" → "SPHEREx detections"; "All 100 photos added together" → "Shift-and-stack of 100 images"
- "The object should sit in the gold circle. Pick a day to see it alone." → "Circle: predicted position. Select a date to see that day's stack."
- "How sure are we?" → "Detection tests"; the checklist labels:
  - Not random noise → **Null-path test** — "0 of 24 offset trajectories reached this S/N."
  - Seen day after day → **Multi-night** — "Detected on 3 of 9 nights individually (S/N ≥ 2)."
  - Only at the right time → **Time-shift test** — "S/N peaks at Δt = 0 and drops for ± shifts."
  - Still there without the stars → **Static-sky subtracted** — "S/N 5.6 after reference-image subtraction."
  - Bright enough to see here → **Injection–recovery** — "100% of synthetic sources at the predicted magnitude recovered."
  - Fits the orbit → **Orbit consistency** — "Refit RMS 0.71″ (was 0.70″) with 1 added position."
- "Where is it going?" → "Orbit uncertainty"; "Smaller is better" → delete.

**Benchmark (`src/views/benchmark.ts`, `src/views/benchmark/logic.ts`, engine `benchmark.py`)**

- Title "Does it work?" → "Blind recovery test"

- Card text: "Rewind found it blind, 0.1 arcsec from its true position." → "Recovered 0.1″ from the JPL position."
- "Rewind said Too faint and did not guess." → "Classified TOO FAINT (no false detection)."
- "Hidden from 23 Nov 2025" → "Arc truncated after 23 Nov 2025"
- The three steps (Hide / Search blind / Compare) → (Truncate arc / Blind shift-and-stack / Compare with JPL)

**Scientists (`src/views/scientists.ts`)** — mostly fine already; it is the best page. Fix 1.3, 1.16,
add a "Limitations" section (single-band PSF photometry, linear covariance, no MPC submission,

**About (`src/views/about.ts`)**
- "Rewind finds new comets and asteroids in older NASA SPHEREx photos" → "Rewind finds precovery detections of recently discovered asteroids and comets in NASA SPHEREx survey data."
- "First light: 102 infrared colours" → "102 spectral channels, 0.75–5.0 µm"
- Remove the duplicate stat block (keep it on Home + Scientists only).

**Games (`src/views/detectives.ts`, `games/*.ts`)**

### 2.2 Global wording sweep

Run `grep -rniE "photo|colour|dots?\b|anyone else|nobody knew|made-up|did not guess|blind|pretend" web/src engine/rewind_engine`
and fix each hit against the glossary. Keep "photo" only in the Games/intro where a lay reader is
explicitly addressed. Replace " - " separators in labels with " · " or "–".

### 2.3 Units and formatting
- Always `″` / `arcsec`, `µm`, `AU`, `km`, `S/N`; give dates as `15 Sep 2026` and, in tables, ISO.
- Distances on Stars page: `pc` first, `ly` in parentheses, everywhere.
- Numbers: thin space or comma for thousands consistently (`1,628,230`).

### 2.4 Verdict definitions (one place, reused everywhere)
Define FOUND / HINT / TOO FAINT / NO DATA once in a shared module (e.g. `src/lib/verdicts.ts`) and
render the same short definition in the results list tooltip, object panel badge, benchmark legend
and scientists table. Rename "Known, seen" → "Control (known object)".

## Phase 3 — UX fixes

1. **Two panels open at once.** Opening an object while a flash photo-card is open leaves both
   visible and overlapping (desktop: card left, panel right, scene squeezed). Close the photo card
   when the object panel opens (`src/ui/photocard.ts` + `select()` in `src/main.ts`).
2. **Guided intro hijacks the user.** After "Start the rewind" the timeline auto-plays and cards pop
   open on their own. Make every step user-advanced (Next / Skip tour), show step `2 / 5`, and
   remember "tour done" in `localStorage` (wrapped in try/catch).
3. **Captions overlap the Sun** and labels on the 3D scene during the intro. Put captions in a
   fixed band above the timebar with a solid backdrop.
4. **Hero CTA is vague.** Two buttons: primary "Explore the precoveries", secondary "How it works"
   (→ `#/scientists#method`).
5. **Navigation.** The hamburger hides all six pages on desktop. Show a top nav on ≥1024 px:
   Explore · Results · Method · Blind test · Games · About. Keep the hamburger only below 1024 px.
6. **Timebar meaning.** "7d/s", "PAST / TODAY / FUTURE" and coloured blobs have no legend. Add a
   tooltip/legend: "Coloured marks = SPHEREx detections. Speed: simulated days per second."
7. **Results list**: "Show all 265" dumps a long list. Add a filter by verdict + sort by lead time /
   S/N, and show lead time as a number column.
8. **Object panel**: the big "13 days" card is good; add discovery date and SPHEREx earliest date
   side by side under it so the number can be checked at a glance.
9. **Empty/loading states**: skeletons for panel tabs and image strips; never show "0".
10. **Stars map**: "Click the map, then scroll to zoom" is wrong on touch; use pinch on touch,
    `ctrl/⌘ + wheel` on desktop, and keep the +/- buttons. R Dra label is clipped at the top and
    overlaps the heading on tablet; constrain labels to the canvas safe area.
11. **About hero image** (giant grey cone) dominates the page — crop or replace with the SPHEREx
    sky-map image, max-height 50vh.
12. **Accessibility**: tab buttons in the panel have no accessible name (`role=tab` with empty text
    in the a11y tree) — add `aria-label`. Check contrast of mono 10–11 px labels (`--ink-3` on
    near-black likely fails AA). Respect `prefers-reduced-motion` for the auto camera moves.
13. Run the `design-review` / `qa` skill after Phase 3 on desktop, tablet and phone.

## Phase 4 — 3D and asset loading performance

Measured on the live site (desktop, cold load): **~1.2 MB transferred before any interaction**,
one **851 KB (252 KB gz) JS bundle** containing three.js + every page, **both** `poster-m.jpg`
(175 KB) and `poster.jpg` (293 KB) downloaded, 7 `object.json` files (≈1.4 MB decoded) prefetched
for the showcase, `orbits.bin` 4.3 MB loaded on "Start".

Do these in order, measuring after each with Lighthouse (mobile preset) and `performance.getEntriesByType('resource')`:

1. **Split the bundle** (`vite.config.ts`, `src/main.ts`)
   - Lazy-load every page view: `const VIEWS = { sky: () => import('./views/sky'), … }` and update
     `PageHost.open` to await the module. These pages don't need three.js.
   - Lazy-load the stars 3D viewer (`views/stars3d/*`) only when that page opens.
   - `build.rollupOptions.output.manualChunks: { three: ['three'] }` so three.js is cached separately.
   - Import only what's used from three (`import { WebGLRenderer, … } from 'three'`); avoid
     `three/examples` addons unless needed.
   - Target: initial JS < 120 KB gz; three chunk loads in parallel.
2. **Poster image**: serve one, chosen by media query, instead of both:
   `<link rel="preload" as="image" href="poster.webp" imagesrcset="poster-m.webp 800w, poster.webp 1600w" imagesizes="100vw" fetchpriority="high">`
   and set it as the CSS background with `image-set()`. Convert to WebP/AVIF (expect −60%).
   Remove whichever JS path sets the second poster.
3. **Fonts**: you load 6 Geist weights (sans 400/500/600/700, mono 400/500). Cut to 3 (sans 400,
   600; mono 500) or switch to the variable font; add `font-display: swap` and preload the one used
   by the hero title.
4. **Data loading strategy**
   - `index.json` (159 KB decoded): precompress (`.br`/`.gz`) and check Railway serves
     `Content-Encoding`; add `Cache-Control: public, max-age=31536000, immutable` for hashed assets
     and a short max-age + ETag for `/data/*`.
   - Don't prefetch 7 full `object.json` files at startup. Put the few fields the showcase/flash
     needs (name, flash photo URL, dates, orbit elements) into `index.json`; load `object.json`
     only when the panel opens. `refine()` for FOUND objects can run in `requestIdleCallback`.
   - `orbits.bin` (4.3 MB): quantise to Float16/Int16 where precision allows (angles in 1e-4 deg
     are fine for display), drop unused columns, and brotli it — target < 1 MB. Stream it with
     `fetch` + progress indicator, and start the fetch on hover/focus of the CTA
     (`<link rel="prefetch">`), not on click.
   - Move orbit parsing + Kepler propagation of tens of thousands of points to a Web Worker
     (there is already a worker pattern in `src/views/sky/worker.ts`) and transfer the
     `Float32Array` back.
5. **Rendering**
   - `Scene.ts` uses `logarithmicDepthBuffer: true` — expensive on mobile GPUs; only needed if you
     see z-fighting; try a tighter near/far instead.
   - Render on demand: stop the RAF loop when nothing moves (no playback, no camera damping, tab
     hidden) — `Scene.ts:750` loops forever. Add a `visibilitychange` pause like `stars3d/scene.ts` has.
   - Asteroid cloud: one `Points` with a custom shader; positions updated in the vertex shader from
     orbital elements + time uniform (no per-frame CPU loop over all orbits). On phones cap the
     number of background asteroids (e.g. 15k) and keep `pixelRatio` ≤ 1.5.
   - Dispose geometries/materials/textures when leaving the stars 3D page (check for leaks with
     `renderer.info.memory` before/after navigating away and back).
   - Image strips/frames: use `loading="lazy"` + `decoding="async"`, and preload only the next
     frame in an animation, not all 16.
6. **Perceived performance**: show the static poster + hero text immediately (no JS needed),
   fade the WebGL canvas in once the first frame renders, and show a thin progress bar while
   `orbits.bin` loads.
7. Add `web/scripts/bench-load.mjs` (Playwright is already a dev dependency) that records transfer
   size, LCP and time-to-first-3D-frame for desktop and a throttled mobile profile, so regressions
   are visible.

## Phase 5 — Tablet and phone

Breakpoints currently used: mainly `max-width: 720px` plus a scattered few. Standardise on tokens
in `src/styles/tokens.css`:

```
--bp-phone: 600px    (≤ 599 phone)
--bp-tablet: 1024px  (600–1023 tablet, portrait and landscape)
```
(CSS custom properties can't be used inside `@media`; declare them as comments + use the same
literal values, or adopt `@custom-media` via PostCSS.) Also use `(pointer: coarse)` for touch-only
behaviour rather than width.

### Bugs found
1. **Phone: hero is invisible.** At 375×812 the `.opening` layer is present but `.op-title` stays at
   `opacity: 0` (stuck in the `rise` animation), so a phone visitor sees an empty star field with
   no headline or CTA. Make the hero visible by default (`opacity: 1`) and apply the animation only
   under `@media (prefers-reduced-motion: no-preference)`; verify on a real iPhone/Android too.
   Also on phones the heavy 3D data isn't loaded until interaction (`if (!isPhone || deepLink) loadHeavy()`),
   so the scene looks empty — show the poster image behind the hero on phones.
2. **Tablet (768×1024): object panel renders ghosted** — semi-transparent over the scene at the
   top, unreadable. The panel's tablet state falls between the phone bottom-sheet rule and the
   desktop side-panel rule (`src/ui/panel.css` uses `min-width` and `max-width` queries that leave
   a gap). Give 600–1023 px an explicit layout: bottom sheet at 55% height in portrait, side
   panel 380 px wide in landscape.
3. **Phone: object view is cramped.** Bottom sheet + timebar + top view-switcher leave ~200 px of
   3D. Hide the timebar while the sheet is open (show a mini date chip instead); make the sheet
   draggable with snap points (peek 30% / half 55% / full 92%); view-switcher row
   ("Solar system / Orbit / Close-up / Before / After") overflows off-screen — turn it into a
   segmented control that scrolls with fade edges, or a single dropdown.
4. **Scientists page on phone**: the sticky section nav overlaps the page header; the orbit-impact
   table is 860 px wide. Below 600 px render each table row as a stacked card (label: value), or
   keep horizontal scroll inside a wrapper with a visible scroll shadow and a frozen first column.
5. **Stars page**: legend and title overlap the map on tablet; R Dra label clipped. Stack the
   legend under the map below 1024 px.
6. **Touch targets**: several icon buttons and the 10–11 px mono labels are below 44×44 px / legible
   size on phones. Minimum 44 px hit area, 12 px minimum label size.

### General responsive checklist (apply to every page)
- `100dvh` instead of `100vh` for full-screen layers (iOS Safari address bar).
- `env(safe-area-inset-*)` on top bar, timebar, bottom sheet (partially done).
- No horizontal page scroll at 360 px; 16 px side gutter.
- Fluid type with `clamp()` for headings (hero already does).
- Images: `srcset` + `sizes` for NASA images in `public/img/nasa/` (they're full-size JPGs).
- Hover-only UI (benchmark cards "Hover or tap") → make tap explicit on `(hover: none)`.
- Test matrix: 360×780, 390×844, 768×1024, 1024×768, 1180×820 (iPad landscape), 1440×900;
  run `web/scripts/shot.mjs` at each size and commit the screenshots to `docs/screens/` for review.
