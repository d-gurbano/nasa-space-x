## Problem Statement

SPHEREx maps the whole sky every 6 months in 102 near-infrared bands. Moving and changing objects (asteroids, comets, brown dwarfs, variable stars) show up as shifts between images, but the data is 65 MB FITS files behind flaky archive APIs. The challenge: a public web tool where anyone types a target or coordinates and quickly sees how that patch of sky changes over time.

## What Makes This Cool

- **Two clocks, one player.** SPHEREx sees each spot in bursts of exposures about 2 minutes apart, then again 6 months later. The player has a "Minutes" timeline (movers crawl inside one burst; shown with planted test movers in Practice mode, since the cached real data has almost none) and a "Seasons" timeline (high-proper-motion stars like Barnard's Star shift about 1 to 2 pixels from the first season to the last (under 1 pixel between adjacent passes), made visible with zoom and a predicted-position crosshair). No other blink tool frames time this way, because no other survey has this cadence.
- **The reveal.** WISE 0855 is hard to see in a single frame; stacking all 45 D6 frames brings it out at S/N 13.5. Following its motion adds little (S/N 14.0) because it moves only about 1 px over the year [measured: output/wise0855_D6_motion_stack.png]. The "Stack it" button tells that story honestly: depth reveals it, and the motion-following panel is shown as a comparison, not as the cause.
- **Colour sweep.** SPHEREx's real strength is 102 wavelengths. A mode that orders the cached frames by wavelength instead of time shows the field changing colour: WISE 0855 brightens toward 5 µm, stars fade. It uses only data already exported, and opens the demo.
- **Honest flicker.** Every SPHEREx frame sees a different wavelength, so stars flicker even when nothing changed. Each frame carries a colour chip with its wavelength, and a "Same colour only" toggle restricts the blink to frames within a narrow wavelength window. The tool teaches the public why flicker is not discovery, using the same rule as `fake_mover_filter.py: ON_STATIC_STAR`.
- **Pre-screened candidates.** Circles from `fake_mover_filter.py` overlay the player: green = moving candidate, teal = known asteroid, other colours = artifact type with its reason (see legend) ("cosmic-ray hit", "satellite streak"). Clicking a circle explains what it is. On real fields most circles are artifact-coloured, which is itself the lesson: the filter shows why most "changes" are not discoveries.

## Constraints

- About 24 hours, 2 people.
- IRSA is unreliable: SIA2 returns 502s, TAP and the Data Explorer were down during testing, CDS services mostly down. SIA2 and the cutout service have no CORS. S3 (`nasa-irsa-spherex`) and the HiPS cube do allow CORS.
- Cutouts are about 4 MB each (PSF table attached), in detector orientation, flipped 180° between visits, with SIP distortion. They must be reprojected north-up before blinking.
- Data so far: DR1 + QR3. Cached targets have 6 to 8 "visits" (groups split by a 3-day gap) spanning about one year, i.e. 2 to 3 six-month survey passes per position [measured: output/*_frames.csv, wise0855 MJD 60800 to 61171].
- Proper motions are small on the SPHEREx grid: Barnard's Star 10.4″/yr ≈ 1.7 px/yr, WISE 0855 8.1″/yr ≈ 1.3 px/yr, Epsilon Indi B 4.7″/yr ≈ 0.8 px/yr at 6.15″/px [measured: spherex_try.py:64-80 TARGETS pm values]. Between adjacent 6-month passes that is under 1 pixel (Barnard ≈ 0.85 px); first-to-last season over one year is 1-2 px, so the player needs zoom and a predicted-position marker to make it visible.
- Real-data mover candidates are rare: 3 CANDIDATE rows total (all Barnard's Star field), 0 KNOWN_OBJECT, across the 4 filtered targets [measured: output/*_movers.csv]. Most circles on real data will be artifacts (coloured by type, see legend).

## Premises (agreed)

1. Interface: type a target or coordinates, watch it change. Frame player with timeline, north-up, per-frame date and wavelength labels.
2. A thin Python layer is required (no CORS on SIA2, heavy cutouts). It reuses `spherex_try.py` and `fake_mover_filter.py`, no JS rewrite of the science.
3. The demo must not depend on IRSA being up during judging: featured targets are precomputed and served as static files.
4. Timebox is about 24 hours (user revised from 48h). Static gallery ships; live any-coordinate queries are a stretch goal.

## Approaches Considered

- **A: Static Blink Gallery.** Precomputed featured targets, static site, canvas player. Effort S, risk low. Chosen as the base layer.
- **B: Live Sky Time Machine.** FastAPI wraps the pipeline for any coordinate, Aladin Lite sky picker, cache. Effort L, risk medium. Chosen, as stretch on top of A.
- **C: Spot the Mover.** Citizen-science voting game on pre-screened candidates. Effort M. Deferred: becomes a post-hackathon extension.

## Recommended Approach

**B built A-first.** The static gallery is both the safe demo and the cache format the live API writes. Every live result is just another target folder in the same format, so the frontend never knows the difference.

Wireframe: none (skipped to protect the 24h timebox; the dev plan below specifies the layout).

### Phase 0: Prep (30 min)
1. Confirm `.venv` works: `.venv/bin/python spherex_try.py --target wise0855` reproduces `output/wise0855_D6_*`. The cutout cache in `spherex_cache/` (1.6 GB, 414 files) covers the 5 test targets, but `search_images` (spherex_try.py:112) calls SIA2 on every run with no cache, so today an export still needs IRSA. Fix: cache each SIA2 response as `spherex_cache/sia_<collection>_<ra>_<dec>.csv` inside `search_images` (read if present, write after a 200). Cache key formats `ra`/`dec` with `.4f`, matching `download_cutout` (spherex_try.py:151). **Blocking task at hour 0:** seed the SIA2 cache for all 5 targets while IRSA is up. Fallback if IRSA is down: rebuild the rows (`obs_id`, `t_min`, `energy_bandpassname`) from headers of the already-cached FITS cutouts.
   - Cached field sizes differ per target [measured: spherex_cache filenames]: wise0855 D6 0.08° and 0.2°, barnard D2 0.05/0.08/0.2°, rwaur D2 0.2°, epsindib D4 0.2°, rdra D2 0.08° only. Export uses the largest cached size per target via an `EXPORT_DEFAULTS` dict so no cutout is re-downloaded.
   - Acceptance: with the network blocked (`HTTPS_PROXY=http://127.0.0.1:9`), `export_web.py --all` succeeds for all 5 targets.
2. Make the pipeline importable without side effects. Refactor `spherex_try.py: main()` so the body after argument parsing becomes `run_field(ra, dec, detector, size_deg, per_visit=None, target=None) -> FieldResult` (`per_visit=None` = every cached row at that size, which is what the export uses) returning in-memory arrays (per-frame reprojected images, rows, visit grouping, wavelengths, masked fraction, motion stack) instead of only writing PNG/GIF. `main()` calls it and keeps writing the same outputs. Same treatment for `fake_mover_filter.py: main()` → `run_filter(ra, dec, detector, size_deg, inject=False, skybot=True) -> dict` returning `{frames_aligned, template, detections, truth}` (`truth` = planted objects when `inject=True`, from `inject()` at fake_mover_filter.py:223). `export_web` passes the same EXPORT_DEFAULTS size to `run_field` and `run_filter` so candidate positions share one grid. Offline export runs with `skybot=False` (SkyBoT is a network call, fake_mover_filter.py:490), so KNOWN_OBJECT/teal appears only on online exports. rdra has no filter run yet; run it at 0.08°.
3. Acceptance: `output/` is gitignored, so before the refactor copy it to `output_baseline/`; after the refactor rerun both scripts with their default settings and `diff` `wise0855_D6_frames.csv` and `wise0855_D6_movers.csv` against the baseline (PNGs may differ).
4. One frame list: `export_web` builds the list of SIA rows that have a cached cutout at the EXPORT_DEFAULTS size and passes it to both `run_field(rows=...)` and `run_filter(rows=...)` (new `rows=` parameter; `run_filter` otherwise picks from all SIA rows via `pick_evenly`, fake_mover_filter.py:532, and would hit uncached rows). Acceptance: every `candidates[].obs_id` appears in `frames[].obs_id`.

### Phase 1: `export_web.py` (2-3 h)
CLI: `.venv/bin/python export_web.py --target wise0855 [--all] [--ra --dec --detector --size] --out web/data`.

Per target writes `web/data/<slug>/`:
- `manifest.json`:
  ```json
  {
    "slug": "wise0855", "name": "WISE 0855-0714", "ra": 133.795, "dec": -7.245,
    "detector": 6, "size_deg": 0.2, "pixel_arcsec": 6.15, "shape": [h, w],
    "practice": false, "pm": {"pmra_mas_yr": -8118.0, "pmdec_mas_yr": 680.0, "epoch": 2010.5, "arcsec_yr": 8.15, "px_yr": 1.33},
    "grid_wcs": {"crval": [ra, dec], "crpix": [x, y], "cdelt": [-d, d], "ctype": ["RA---TAN","DEC--TAN"]},
    "stretch": {"kind": "asinh", "lo": p1, "hi": p99_5},
    "seasons": [{"id": 1, "mjd_start": 60800.7, "visit_ids": [1], "stack_png": "season_1.png"}],
    "visits": [{"id": 1, "season": 1, "mjd_start": 60800.7, "iso": "2025-05-..."}],
    "bursts": [{"id": 1, "visit": 1, "mjd_start": 60800.70, "frame_ids": [0, 1]}],
    "frames": [{"i": 0, "visit": 1, "burst": 1, "obs_id": "...", "mjd": 60800.7000, "iso": "...",
                "wavelength_um": 4.967, "masked_frac": 0.018, "pred_ra": 133.7600, "pred_dec": -7.2422,
                "png": "f000.png", "diff_png": "d000.png"}],
    "motion_stack_png": "motion_stack.png",
    "candidates": [{"ra": 133.68, "dec": -7.30, "x": 104.0, "y": 25.1, "obs_id": "...", "mjd": ...,
                    "verdict": "CANDIDATE", "reason": "moving like a real object, no known match", "planted": false}],
    "credit": "SPHEREx DR1 + QR3, NASA/IPAC IRSA",
    "generated": "2026-11-15T..."
  }
  ```
- PNGs: 8-bit grayscale, upscaled with nearest-neighbour to at most 512 px so pixels stay honest. Stretch: asinh between the 1st and 99.5th percentile of the median template, shared by every frame and every visit stack. NaN (masked) pixels render as a dark blue-grey hatch so users can see masking, not mistake it for sky (red is reserved away from verdicts and the wavelength ramp).
- Difference frames: frame minus median template, symmetric stretch around zero, gray = no change.
- Verdict reasons come from the existing label table in `fake_mover_filter.py` (lines ~102-116), not re-typed.
- Seasons: group visits into survey passes (gap > 60 days) for the Seasons timeline; 3-day visits stay as sub-ticks. Manifest gains `"seasons": [{"id", "mjd_start", "visit_ids", "stack_png"}]`.
- Predicted position: per frame, `position_at(target, year)` (spherex_try.py:104) gives the catalogue-predicted RA/Dec; store as `pred_ra`, `pred_dec` so the player can draw a crosshair. Omitted for custom coordinates (no proper motion).
- Targets (core): the 5 cached ones in `TARGETS`.
- Practice mode (core, as a quiz): the user clicks where they think a planted mover is, then the filter's verdicts and the answer key are revealed; client-only, no accounts. Data: run `run_filter(..., inject=True)` on the wise0855 field (the injection test gave 10 rows there; rwaur gives 0) and export it as `practice-wise0855`, every planted object labelled "planted test object" in the manifest and UI. This is the only honest way to show the Minutes timeline with movers, given 3 real candidates in the cached data.
- Moving targets (stretch, after Phase 3): 3I/ATLAS and one MOST asteroid in "track mode" (cutouts centred on the ephemeris, labelled "camera follows the comet"). New pipeline code and needs IRSA live; drop if not done by hour 18.
- Acceptance: `web/data/index.json` lists all exported targets with a thumbnail; the export validator (plain Python, no `assert`, see Developer contract) checks every manifest against the key list in `web/manifest.schema.md` and that every referenced file exists.

### Phase 2: Frontend `web/` (4-6 h)
Plain HTML + ES modules, no framework, no build step (deploys as files). Only external script: Aladin Lite v3 from jsDelivr, pinned version, used for the sky context panel.

Files:
- `web/index.html`: landing. Hero = WISE 0855 in Colour sweep, autoplaying (stepped frames under reduced motion). Gallery cards from `data/index.json`. Search box: matches featured names, or parses `RA Dec` in degrees or sexagesimal.
- `web/js/player.js`: canvas player. Loads season stacks first, then lazy-loads individual frames when Minutes, Colour sweep or Difference is opened (keeps the phone target under 3 s). Preloads the PNGs of the open mode as `Image` objects, then `requestAnimationFrame` loop. Controls: play/pause (space), step (←/→), speed (0.5 to 8 fps), scrub slider whose stops depend on the mode (see Per-mode slider in the UI spec).
- Modes (segmented control), in build and cut order: **Seasons**, **Colour sweep** (all frames ordered by `wavelength_um`, caption shows µm prominently), **Stack it** (single frame → plain stack → motion-following stack, each with its S/N), **Minutes**, **Difference**. If time runs short, cut from the end of this list. Mode details: **Seasons** (one stack per 6-month survey pass), **Minutes** (individual frames within the burst chosen in a burst dropdown listing date, time and frame count), **Difference**, **Stack it** (three labelled step buttons, see the UI spec).
- Zoom: 1×, 2×, 4× around the target (nearest-neighbour, CSS `image-rendering: pixelated`), default 4× for high-proper-motion targets. Predicted-position crosshair per frame from `pred_ra/pred_dec`, togglable.
- Motion caption for moving targets: "Moves 10.4″ per year, about 1.7 pixels between yearly frames", computed from the manifest's proper motion and pixel scale.
- Per-frame caption: `2025-05-14 03:22 UTC · 4.97 µm · Detector 6`, with a colour chip mapping 0.75 to 5.0 µm onto a fixed perceptual ramp; a mini spectrum bar shows where this frame's wavelength sits.
- **Same colour only** toggle: applies to Minutes and Difference (single frames); disabled in Seasons and Stack it (multi-wavelength stacks) and in Colour sweep (already ordered by wavelength). Filters frames to a ±0.1 µm window around the median wavelength; disabled with an explanation if fewer than 2 frames remain (expected on some fields: rdra keeps 17 of 32 frames, wise0855 8 of 23, barnard 4 of 18 [measured: output/*_frames.csv]).
- `web/js/overlay.js`: candidate circles on an SVG layer over the canvas, positioned via `grid_wcs` (simple TAN projection in JS, 20 lines). Coloured by reason using the filter's existing `REASON_COLOR` palette (fake_mover_filter.py:114), with a legend. A circle shows only on frames whose `obs_id` matches; ON_STATIC_STAR is hidden by default behind a "show stars" toggle because it is dense. Planted objects get a dashed ring and the label "planted test object". Click → popover with verdict, reason, SNR, time.
- `web/js/state.js`: URL state `?t=wise0855&mode=seasons|colour|stack|minutes|diff&frame=3`, or `?ra=&dec=&det=` for live fields. Copy-link button.
- Sky panel (first to cut; hidden silently if the IRSA HiPS or the Aladin script fails to load): Aladin Lite with the SPHEREx HiPS cube (`https://irsa.ipac.caltech.edu/data/hips/SPHEREx/spherex_allsky_cube`) as background, a box marking the field. Clicking elsewhere in Aladin, or typing coordinates that are not a featured target in the search box, proposes a live query (Phase 4) or, if live is off, shows "This spot isn't in our gallery yet. Here are the 5 we've prepared." with the gallery cards.
- "Why does it flicker?" explainer: a short card with one sentence and the colour ramp; trigger rules in the UI spec below.
- Accessibility: all controls keyboard-reachable, captions are real text, reduced-motion users get stepped frames instead of autoplay.
- States: see the exact-copy state table in the UI spec.
- Acceptance: every featured target plays in Chrome, Safari and mobile Safari; no console errors; Lighthouse performance ≥ 90 on landing.

### Developer contract (from DX review)

**Hello world for a teammate (target < 5 min, no cache needed):**
```
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m http.server -d web 8000     # then open http://localhost:8000/?t=sample
```
- `web/fixtures/sample/` is committed (one small manifest + ~6 tiny PNGs, < 200 KB). The player falls back to it when `data/index.json` is missing, and `?t=sample` loads it directly. Frontend work and smoke tests need no cache.
- `requirements.txt` (pipeline) and `api/requirements.txt` (stretch API) are added in Phase 0.

**`export_web.py` CLI:**
- `--target SLUG`, `--all` and `--ra/--dec` are an argparse mutually exclusive group; a lone `--ra` or `--dec` exits 2 with a usage line before any work. Custom coordinates require `--slug` (or derive `ra<ra>_dec<dec>`) and get defaults `default_mode=seasons`, `default_zoom=1`, empty `look_for`.
- `--out` defaults to `web/data`. `--offline` reads only the SIA2 and cutout caches, forces `skybot=False`, and fails fast on a cache miss (the `HTTPS_PROXY=http://127.0.0.1:9` run is the test of this flag). Under `--offline`, `--size` must match a cached size. Online, an uncached size prints "downloading N cutouts (~4 MB each)".
- `--refresh-sia` bypasses and rewrites the SIA2 cache. `--rebuild-sia SLUG` rebuilds rows from cached FITS headers (the IRSA-down fallback). `--format png|webp` (default png). `--force` overwrites an existing export, which is refused by default.
- Per-target `look_for`, `default_mode` and `default_zoom` live in `EXPORT_DEFAULTS` in code, never hand-edited in `index.json`. `index.json` is regenerated on every export from the targets that succeeded.

**Errors (agent-ready):**
- SIA2 cache: cache only when the response parses, has the expected columns and has more than 0 rows; write to `.tmp` and `os.replace`. A target with fewer than 2 frames exits non-zero.
- Typed exceptions in the pipeline: `ExportError` → `CacheMiss` (names the expected file and the fix `run once online` or `export_web.py --rebuild-sia <slug>`), `NoFramesError`, `GridMismatchError` (carry target, detector, size and counts). `main()` maps them to exit 1 plus one stderr line, e.g. `export_web: wise0855: manifest missing keys [bursts]; missing file f012.png` followed by `rerun: export_web.py --target wise0855`. Validation collects all problems; no `assert`.
- Export is atomic per target: write `web/data/.<slug>.tmp/`, rename on success. `--all` continues past a failed target and prints `4 ok, 1 failed: rdra (SIA cache miss)` with a non-zero exit.
- Frontend: every load failure `console.error`s the URL, HTTP status, slug and `schema_version` alongside the public copy.
- Live API (stretch): job states `queued|running|done|failed`. Failures return RFC 9457 problem+json with a stable `type` (`irsa_unavailable`, `no_coverage`, `frame_cap`), `detail` and `retryable`.
