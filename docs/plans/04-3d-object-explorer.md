## 1. What we are building (one paragraph)

Each featured object gets an **object page** with four parts: (1) a **3D view you can rotate**, (2) its **history**, meaning the real SPHEREx frames of it over time from the existing player, (3) its **predicted path** (on-sky track, or a 3D orbit around the Sun), and (4) a **"what is it made of" card**, which pairs catalogue facts with the object's own rough SPHEREx spectrum and reference curves for each asteroid class. One shared **clock** ties the views together. Scrubbing the history moves the object along its orbit to that frame's date.

### The fact the whole design rests on
SPHEREx pixels are **6.15″** wide [measured: spherex_try.py:56 `PIXEL_SCALE_ARCSEC`]. Eros, the biggest small body on the roster, is about 34 km long. Even at its closest approach that is far smaller than one pixel. **No SPHEREx image can ever show a shape.** So:
- Every 3D body mesh is an **AI-generated artist's impression** (decision D2). It is scaled to the real measured size and axis ratios where those are known, and it is **always badged as AI** in the UI.
- Everything else on the page (history frames, path, spectrum, catalogue facts) is **real data** and is badged that way.

### 3.4 Data flows (happy / nil / empty / error)

```
 FACTS:  export_objects.py facts <slug>
   happy : SsODNet 200 + Horizons 200 ──► objects_cache/<slug>/*.json ──► object.json.facts
           stars/brown dwarfs: facts_overrides.yaml (sourced lines) ──► object.json.facts
   nil   : not in SsODNet AND no override (only candidates) ──► facts = {"unknown": true}; card says "Not catalogued"
   empty : field missing (no density) ──► row omitted, never "0" or "NaN" in UI
   error : 5xx/timeout ──► get_with_retry (spherex_try.py:90) 4 tries ──► use cached file if present
           ──► else export FAILS LOUDLY for that object (named in report), others continue

 MESH:   gen_mesh(slug, seeds=[1,2,3])
   happy : ref image ──► GLB ──► postprocess ok ──► contact sheet ──► human approves one seed
   nil   : no FAL_KEY in env ──► exit 2 "set FAL_KEY (offline only)"; export uses poster-less sphere fallback
   empty : GLB with 0 faces / >1 large component / bbox degenerate ──► seed marked rejected:auto
   error : 4xx/5xx/timeout/refusal ──► 2 retries with backoff ──► seed marked failed, others continue
           ──► if no approved seed: object ships with model.kind="sphere" + note "3D model pending"

 SPECTRUM: per frame aperture flux at object position (track-mode centre, or pred position)
   λ     : wavelength_at(hdul, ra, dec) (spherex_try.py:162) at the OBJECT's position in each
           frame (the filter varies across the chip), never the field centre
   geom  : flux × r²Δ² (Sun and observer distances, from MOST rows / Horizons) and a simple
           H-G phase correction, so frames months apart are comparable
   rot   : lightcurve (Eros swings up to ~1.5 mag) is not removable, so the TEMPLATE
           comparison uses points from ONE visit (minutes-hours apart, the visit with most
           points); other visits are drawn faded as "other dates"
   happy : finite flux, S/N ≥ 3 ──► point (reflectance = flux / solar(λ), normalised at
           ~1.6 µm, outside the S-type 1 µm absorption band)
   thermal: zone above which heat dominates scales with r and albedo (≈ 3.5 µm for Eros
           near 1.1-1.8 AU); computed per object at export, points there drawn hatched
   nil   : object off-frame / masked ──► frame skipped, counted in "N of M frames used"
   empty : < 5 usable points ──► spectrum panel shows "Too faint for a SPHEREx spectrum here"
   error : NaN centroid ──► skip frame (never plot NaN)

 PATH:  orbit3d from Horizons VECTORS; sky_track from position_at (spherex_try.py:104),
        which takes a DECIMAL YEAR: convert with astropy Time(mjd, format="mjd").decimalyear;
        sky_cone from fit_line (fake_mover_filter.py:378) residuals
   empty : < 2 detections for a candidate ──► no cone, text "seen once — no direction yet"
   error : Horizons unreachable at export ──► cached response; none ──► path omitted + "Path unavailable"
```

### 3.5 State machines

**Clock (accepted E2).** Exactly one writer: the scrub slider, owned by `clock.js` (eng review: moved from player.js so the mobile clock bar can live outside the History panel). The player and canvas3d only read. There is no separate date slider. It moves in frame steps, so the clock date is always a real frame date and the History view can never sit "between frames".
```
            player.frameChange(mjd)   ◄── player scrub slider / play / ← →
                   │
                   ▼
   ┌─────────┐  set(mjd, src)  ┌──────────────────────────────┐
   │  INIT   │───────────────► │ READY {mjd, src, playing}    │──► notify(orbitScene, skyTrack, caption)
   └─────────┘  (first frame)  └──────────────────────────────┘     (readers never call set)
                                   │ set(same mjd) ──► ignored (no notify)
                                   │ set(mjd outside path range) ──► clamp + flag "outside predicted range"
   Invalid: a reader calling set() ── prevented by API: readers get subscribe() only.
```
The clock deals in plain MJD numbers. Frames already carry `mjd` (base manifest). Orbit samples are interpolated linearly between their 2-day samples.

**Mesh lifecycle (offline):**
```
 queued ─► generating ─► generated ─► auto_checked ─┬─► awaiting_review ─► approved ─► exported
                │                                    └─► rejected:auto
                └─► failed (retries exhausted)          awaiting_review ─► rejected:human
 Export accepts ONLY "approved". There is no path from generated straight to exported.
```

### 3.6 Coupling, scale, single points of failure
- **New coupling:** object.html embeds `player.js`. The only contract is `player.on('frame', mjd)`, a single event added to the existing player. The player does not import the clock; object.html wires them together. Before: player standalone. After: player plus one event emitter. That is justified, and nothing else changes.
- **Scale:** static files, so 10× or 100× visitors costs only GitHub Pages bandwidth. Per object page: three.js ≈ 170 KB gz plus GLB ≤ 2 MB plus frames. The first thing to break at 100× is the Pages soft bandwidth limit (100 GB/month), which is far away.
- **SPOFs during the build:** (1) IRSA up when track_export first runs (by hour 4), (2) fal up for meshes, (3) Horizons and SsODNet. All three are **offline, early, cached**. During judging the only SPOF is GitHub Pages, because three.js is vendored.
- **Rollback:** revert the last gh-pages publish (`git -C gh-pages-worktree reset --hard HEAD~1 && git push -f`), about 2 minutes. Or delete `web/data/objects/index.json` and republish: the gallery hides every "Explore in 3D" link when that index is missing.

## 6. Security & threat model

| Threat | Likelihood | Impact | Mitigation in plan |
|---|---|---|---|
| `FAL_KEY` leaks into the public site or the repo | Med | High | Key in env only, read by `gen_mesh.py`. The validator greps `web/` for key patterns and `.env`. `.env` in .gitignore. The site makes no runtime AI calls. |
| Malicious or oversized GLB from the provider | Low | Med | Post-processing re-exports through trimesh (geometry only plus one texture). Size and triangle limits are enforced by the validator. |
| XSS from catalogue text (SsODNet/JPL strings) | Low | Med | All text goes through `textContent`, never `innerHTML`. Strings are capped at 300 chars at export. |
| URL param `?o=` path traversal | Low | Low | Slug must match `^[a-z0-9-]{1,40}$` **and** exist in `objects/index.json`. Otherwise show the error state. |
| Supply chain (three.js) | Low | Med | Exact pinned version, vendored copy checked into `web/vendor/three/`. |
| Misinformation: AI mesh taken as real shape | **High** | Med (NASA judges, public) | Permanent on-canvas badge, provenance in object.json and GLB extras, "real size, invented surface" wording. Never shown without the badge. |

There is no PII, no accounts, no new endpoints and no prompt injection surface: prompts are built from our own cached JSON, not user input.

## 9. Performance

- Landing page: **unchanged**, because three.js is never requested there.
- object.html budget on 4G: poster < 1 s, interactive 3D < 3 s. Assets: three core + addons ≈ 170 KB gz, GLB ≤ 2 MB (≤ 20k triangles + one 1024² JPEG texture; no meshopt, since that needs Node tooling we don't have), object.json < 60 KB.
- Rendering: `setPixelRatio(min(devicePixelRatio, 2))`, a single directional "Sun" light, no shadows, and a pause when hidden. The orbit view uses `THREE.Line` polylines (< 2 000 points).
- Slowest new paths: (1) offline gen_mesh, 1-3 min per seed at the provider [estimated], run in the background from hour 4. (2) track-mode download, 40 cutouts × about 3 s [measured: resources report §1.3], 6 in parallel. (3) GLB decode on a phone, about 300 ms [estimated].

## 10. Observability

The site is static, so observability means build-time reports and clear console lines:
- `export_objects.py` writes `web/data/objects/report.json` and prints a table. Per object: model source/seed/approved, frames used for the spectrum (N of M), path type and sample count, facts sources and fetch dates, and warnings. **Consumer:** `validate_objects` reads it to fail the publish. The README links it. It retires with the hackathon.
- Browser: `console.warn('[obj]', event, {slug, ...})` for `glb_failed`, `webgl_unavailable`, `three_load_failed`, `clock_clamped`. Nothing is sent anywhere, because there is no analytics.
- `gen_mesh.py` keeps a `objects_cache/meshes/<slug>/log.jsonl`: one line per call with endpoint, seed, duration, status and prompt.
